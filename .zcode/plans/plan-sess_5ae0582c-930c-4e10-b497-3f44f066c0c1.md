# Financial Agentic System — Audit Fixes + LLM Integration Plan

## Part A — Critical contract bugs

**A1. Graph loader ↔ retrieval ID contract** (`agent/tools/graph_tool.py`, `ingestion/entity_extractor.py`, `ingestion/graph_loader.py`)
- `graph_tool.query_metrics`: build `metric_id` with the loader's slugify rules (`metric::operating_income`, not `metric::operating income`); extend company WHERE to match `c.id` slug form (`company::amazon_com_inc`) in addition to ticker-form `c.id` and `CONTAINS` on name. Local `_slugify` helper with a cross-reference comment to `ingestion/graph_loader.py:slugify` (ingestion must not import agent).
- `entity_extractor._extract_company_identifier`: accept single-char company codes (V, C are real FinQA company dirs) — currently `len < 2` drops them, so those records load as unreachable "Unknown Company" nodes (24+ records in dev alone).
- Tests: exact-match path now hits for both ticker and slugged-name inputs; metric slug equality with loader convention.

**A2. IR evaluation metrics structurally zero** (`evaluation/metrics.py`, `evaluation/evaluator.py`)
- Gold keys are `table_3`/`text_34` but evaluator compares row-label strings and `pre_text_0`-style keys → recall/precision/MRR/NDCG can never be non-zero on real data (tests pass only because they use synthetic IDs).
- Fix: add `compute_ir_metrics_content(retrieved_texts, gold_evidence_texts)` scoring gold evidence by normalized token overlap against retrieved content (graph row_label+amount text, chunk text_content); evaluator passes texts instead of IDs; keep old function for compatibility. Update tests with real FinQA key/text formats.

**A3. Regression/eval chain broken** (`evaluation/runner.py`, `evaluation/run_regression.py`)
- `runner.py`: write per-record final states to `eval_results/states/{record_id}.json` (`--save-states`, default on) and emit `benchmark_results.json` with the full per-record results list.
- `run_regression.py`: remove dead `FIXTURE_STATE`; if state files missing → fail with a clear "run evaluation/runner.py first" message; go live ONLY with `--live` (never silently in CI). Handle "dir exists but empty".

**A4. gate.py** — no code change needed once A3 emits `benchmark_results.json` (field names `record_id`/`execution_correct` already match); update docstring paths.

**A5. `docker-compose.prod.yml`**: `redis/redis-stack-server:latest` (RedisSaver needs RediSearch/ReJSON — plain redis silently degrades HITL durability to MemorySaver); add the service-hostname env overrides (`NEO4J_URI`, `POSTGRES_HOST`, `REDIS_URL`, `MLFLOW_TRACKING_URI`, LangSmith EU endpoints) that dev compose already has — prod currently points DB connects at `localhost` inside the container; add the missing `mlflow` service.

**A6. K8s probes**: add root-level `/health` (plus `/healthz`) to `agent/server/app.py` — probes currently hit `/health` but the gateway only serves `/api/v1/health` → CrashLoopBackOff. Point UI `_backend_is_live` at `/health` for an accurate check (currently hits `/`, gets 404, shows "online" because 404 < 500).

**A7. `knowledge/vector_store/loader.py`**: `query_similarity` passes a raw Python list where `%s::vector` needs a string literal (always fails) — fix like `vector_tool.py` does; create the ivfflat index lazily after load (count ≥ threshold), mirroring `episodic.ensure_vector_index` — currently created on an empty table.

## Part B — High-priority fixes

**B1. Perf — model reload per call**: new `agent/tools/_clients.py` with `@lru_cache` singletons for `SentenceTransformer`, `VectorRetrievalTool`, `EpisodicMemoryStore`, `MemoryRetrievalTool`; tool entrypoints use them (injectable `client` params kept for tests). Currently the encoder loads from disk on every retrieval/memory call (~1–2s each, multiplied under fan-out).

**B2. UI `_DEFAULT_API_URL`**: use the actual `API_URL` value (`os.getenv("API_URL") or "http://127.0.0.1:8000"`), not just its truthiness.

**B3. `api/main.py`** dead stub → re-export `from agent.server.app import app` so `uvicorn api.main:app` serves the real gateway.

**B4. Small correctness**: fix `env.get("tool_name")` evaluated before `isinstance(env, dict)` guard in `synthesize_node.py` + `retrieval_node.py` (evaluator.py already has the safe order); add missing `Any` import in `agent/graph.py`.

**B5. `graph_loader.py --dry-run`**: implement the flag README already documents (collect payloads, print would-be stats, skip DB).

**B6. MCP bridge schema**: `client_bridge.list_tools_async` reads `t.parameters` — always empty on mcp≥1.x; try `inputSchema` first, fall back to `parameters`.

## Part C — LLM integration (planner + synthesizer)

**C1. `agent/llm.py`** — provider module: lazy ChatOpenAI via `langchain_openai` (env: `OPENAI_API_KEY`, `OPENAI_MODEL` default `gpt-4o-mini`, `OPENAI_BASE_URL` override), token/cost capture into `agent/telemetry`, and **graceful degradation**: no API key or call failure → fall back to existing deterministic decomposer/template so eval and CI stay runnable offline.

**C2. LLM planner** (`plan_node.py`): new `agent/prompts/planner_v2.txt` as system prompt; LLM emits SubTask JSON (pydantic-validated: `target_tool` literal, payload keys, dependency ordering); on parse failure after retry → `decompose_query` fallback. Version hash already flows into scratchpad logging.

**C3. LLM synthesizer** (`synthesize_node.py`): new `synthesizer_v2.txt`; input = fused context + math results + question; output = grounded, citation-bearing analysis. **Anti-hallucination post-check**: extract numerals from LLM output, verify each appears in the evidence strings; on violation → deterministic template answer. Token cap + timeout.

**C4. Telemetry**: per-call tokens/cost logged (Phase 12 hook), model + prompt version in scratchpad.

**C5. Tests**: fake LLM (canned JSON/tool-call responses, monkeypatched provider) for planner/synth paths; fallback-path tests; all existing deterministic tests stay green.

## Part D — CI + polish

**D1. `.github/workflows/ci.yml`** (Phase 15): ruff → mypy(`agent/`) → pytest → pip-audit → `run_regression.py --min-accuracy 0.7`. Regression runs in fixture mode; requires committed `eval_results/states/` fixtures — I'll generate a small set (~10 records) via the runner if a live DB is available, otherwise the CI step reports "no fixtures, skipping" without failing, and the step is marked to activate once fixtures land.
**D2. UI OVERRIDE rework**: OVERRIDE opens a JSON editor prefilled with the thread's `pending_tool_calls`; submits as `overrides.tool_calls` (the only override shape `hitl_gate_node` consumes — today's arbitrary JSON is silently ignored). Validation errors surfaced.
**D3. Lazy audit ledger**: `get_audit_ledger()` singleton with first-use init instead of module-import DB connect (`hitl_nodes.py` currently attempts Postgres at import — slow/fails awkwardly in offline test runs).
**D4. `compute_node` dependency resolution**: prefer the retrieved record whose `row_label` overlaps question terms (shared term-overlap helper with the synthesizer), else first record — today it's always `records[0]`.
**D5. Minor**: `.env.example` `REDIS_URL` add `/0`; prune terminal threads from `ACTIVE_THREADS` in the approvals listing; README/api docs touch-ups where contracts changed.
